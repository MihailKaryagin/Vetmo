# vetmo: 50 идей для развития

Главный сценарий: игрок находит подходящий состав, получает ответ капитана и приходит на игру. Первый релиз стоит оценивать по этому пути. Остальные идеи можно выбирать отдельно под задачи гильдии. Чекбокс означает предложение к рассмотрению, а не подтверждённый дефект.

## 1. Главная и навигация

- [x] **01. Поднять «Найти пати» в шапке.** На телефоне оставить быстрый переход рядом с кнопкой меню, чтобы не искать его среди ссылок.
- [ ] **02. Объединить разделы по смыслу.** Проверить на игроках вариант «Гильдия» (новости, дневник, о нас) и «Соревнования» (матчи, турниры); сравнить, где быстрее находят нужную страницу.
- [x] **03. Вынести ближайшую подходящую пати на главную.** Показать свободную позицию, время в часовом поясе игрока и заполненность состава. Если совпадений нет — дать переход ко всем объявлениям.
- [x] **04. Возвращать к начатому делу.** Для игрока с принятым откликом заменить предложение искать новую пати на «Твоя игра сегодня — подтвердить участие».
- [x] **05. Различить две заявки.** Рядом с «Хочу в vetmo» пояснить, чем вступление в гильдию отличается от отклика в состав на один вечер.

## 2. Поиск пати

- [x] **06. Добавить быстрый поиск «Сегодня вечером».** Показать конкретный интервал и позволить его сдвинуть: для одного игрока вечер начинается в 18:00, для другого — в 22:00.
- [x] **07. Расшифровать совпадение по времени.** Вместо общего «расписание подходит» написать «Вы оба свободны в пятницу с 20:00 до 22:00». Отличать общее свободное окно от назначенной игры.
- [x] **08. Сохранять поиски.** Игрок один раз задаёт «позиция 4, будни, после 21:00» и открывает эту подборку из кабинета.
- [x] **09. Помогать при пустой выдаче.** Предлагать ослабить один фильтр с понятным эффектом: «Без ограничения MMR найдётся ещё 2 пати». Остальные условия сохранять.
- [x] **10. Убирать устаревшие объявления.** Дать капитану срок набора и действие «Продлить»; истёкшие объявления убрать из активного поиска, сохранив историю откликов.

## 3. Отклики и сбор состава

- [x] **11. Собрать историю отклика в одном месте.** Показывать «Отправлен → Принят → Игра назначена» с датами и ближайшим действием игрока. Для отказа и отмены показывать отдельный исход.
- [x] **12. Дать капитану сводку по свободной позиции.** Рядом с откликами на одну роль вывести пересечение расписаний и пул героев, чтобы не открывать каждый профиль отдельно.
- [x] **13. Показывать последствия замены заранее.** Перед изменением запланированного состава объяснить капитану, что время игры и подтверждения участников будут сброшены.
- [x] **14. Искать замену одним объявлением.** Если перед игрой выбыл саппорт, предложить капитану открыть набор именно на освободившуюся роль, не создавая состав заново.
- [x] **15. Предложить повторную игру.** После матча капитан выбирает «Собраться ещё раз»; прежние участники получают приглашения, но место подтверждают сами.

## 4. Профили и кабинет

- [x] **16. Предпросмотр «Как меня видят другие».** Показывать именно публичную версию профиля, чтобы игрок мог проверить видимость контактов и расписания.
- [x] **17. Помочь заполнить полезные поля.** Вместо процента заполненности объяснить пользу: «Укажи время игры — увидишь пати с пересечением по расписанию».
- [x] **18. Разделить основную и запасную позицию.** В подборе сначала показывать совпадения по основной роли; капитану явно отмечать, когда игрок готов сыграть на замене.
- [x] **19. Сделать временный статус «Ищу команду».** Игрок выбирает период, например до воскресенья. После него статус сам снимается.
- [x] **20. Собрать ближайшие дела в кабинете.** Упорядочить по времени игры, события и действия, требующие ответа. Историю оставить ниже расписания.

## 5. События и турниры

- [x] **21. Показывать место в очереди.** Для заполненного события выводить «Ты второй в очереди» и пояснять, что произойдёт при освобождении места.
- [x] **22. Сравнивать запись с личным расписанием.** При пересечении события с уже подтверждённой игрой показать предупреждение и обе даты, оставив решение игроку.
- [x] **23. Рассылать изменения события участникам.** При переносе показывать старое и новое время в одном уведомлении; предлагать отменить запись, если дата не подходит.
- [x] **24. Дать мобильную версию турнирной сетки.** Наряду со схемой показать список серий по раундам. Ближайший соперник должен быть виден без горизонтальной прокрутки.
- [x] **25. Добавить страницу игрового дня.** Объединить сегодняшние серии, время старта, результат и ссылку на разбор; у незавершённой серии не показывать победителя.

## 6. Матчи и контент

- [x] **26. Добавить таймкоды к разбору.** Автор отмечает «12:40 — драка за руну» и объясняет решение. Читатель может перейти к эпизоду, если у записи есть видеоссылка.
- [x] **27. Отмечать источник статистики.** Разделить заметки автора и данные OpenDota, рядом с импортированными числами показать дату обновления.
- [x] **28. Связать разборы по игровой теме.** После материала про вижен предложить другие разборы по теме, а не просто последние публикации.
- [x] **29. Публиковать задачу на разбор.** Показать стоп-кадр или описать ситуацию, предложить выбрать решение в опросе, а объяснение капитана открыть после ответа.
- [x] **30. Сделать итог недели.** Дать редактору черновик с завершёнными сериями, опубликованными разборами и ближайшими событиями; перед публикацией он выбирает главное.

## 7. Уведомления и поддержка

- [x] **31. Разделить уведомления по срочности.** «Подтверди игру» показывать выше информационных сообщений; после подтверждения убирать призыв к действию.
- [x] **32. Настраивать напоминания.** Дать игроку выбрать, нужен ли сигнал за час до игры; при переносе отменять напоминание на старое время.
- [x] **33. Собирать однотипные сообщения.** Капитану показывать «3 новых отклика на позицию 5» с переходом к списку вместо трёх одинаковых карточек.
- [x] **34. Показывать состояние чата при потере сети.** Отличать «отправляем» от «доставлено»; при ошибке сохранять текст и давать повторить отправку.
- [x] **35. Добавить оператору шаблоны ответов.** Например, «Как встать в очередь» со ссылкой на нужный раздел; оператор может отредактировать текст перед отправкой.

## 8. Мерч и заказы

- [x] **36. Показывать доступные варианты до заказа.** На карточке одежды сразу обозначать размеры в наличии; отсутствующий размер нельзя выбрать случайно.
- [x] **37. Добавить таблицу замеров.** Для одежды указывать реальные замеры в сантиметрах, чтобы размеры разных моделей можно было сравнить.
- [x] **38. Сделать историю заказа понятной покупателю.** Для каждого статуса пояснить, что он означает и кто делает следующий шаг; для отмены показать итог явно.
- [x] **39. Связать заказ с поддержкой.** В кабинете добавить «Вопрос по заказу»: в черновик сообщения подставлять номер заказа без платёжных или контактных данных.
- [x] **40. Предусмотреть недоступное фото товара.** Если внешний источник не ответил, сохранить размеры карточки и показать название товара вместо сломанного изображения.

## 9. Мобильный интерфейс и доступность

- [x] **41. Заменить внешнюю миниатюру логотипа локальным файлом.** Шапка и подвал будут показывать один и тот же знак даже при недоступности стороннего сервиса.
- [x] **42. Пройти путь игрока с клавиатуры.** От главной до отправки отклика фокус всегда виден; после закрытия меню или чата он возвращается к открывшей кнопке.
- [x] **43. Проверить соседство кнопок на телефоне.** Разнести «Принять» и «Убрать из состава» так, чтобы при работе большим пальцем их было трудно перепутать.
- [x] **44. Облегчить декоративные эффекты.** При системной настройке уменьшения движения убрать необязательные анимации; проверить читаемость текста поверх стеклянных фонов.
- [ ] **45. Проверить главное действие при открытой экранной клавиатуре.** В отклике, фильтрах и чате кнопка отправки и ошибка поля должны оставаться достижимыми без закрытия формы.

## 10. Проверки и сопровождение

- [x] **46. Проверить гонку за последним местом.** Два одновременных отклика на один слот не должны приводить к двум принятым участникам на одной позиции; проверить на MySQL.
- [x] **47. Закрепить примеры для часовых поясов.** Проверять подбор, отображение и экспорт `.ics` на одной и той же игре: пятница у капитана, уже суббота у участника.
- [x] **48. Репетировать восстановление резервной копии.** Помимо проверки контрольной суммы, периодически восстанавливать копию в отдельную базу и проверять составы и регистрации.
- [x] **49. Измерить задержку списка игроков.** На реалистичном объёме демоданных записать время ответа и число SQL-запросов для страницы с фильтрами; сравнить до и после оптимизации.
- [x] **50. Измерять путь до игры.** Считать переходы «открыл объявление → откликнулся → принят → подтвердил время». Отдельно смотреть, сколько откликов ждут ответа капитана больше суток.

## С чего начать

1. **Проверить исходную точку.** Попросить трёх игроков с телефона найти пати на свою роль. Записать, где они остановились, сколько времени искали и поняли ли, что делать после отклика.
2. **Первый релиз: № 01, 03 и 11.** Это один законченный маршрут: заметить поиск → выбрать состав → узнать судьбу отклика. Повторить тот же сценарий с новыми игроками.
3. **Дальше выбирать по наблюдениям.** Если выдача пустая — № 09 и 10; если отклики остаются без ответа — № 12 и 33; если составы набираются, но люди не приходят — № 22 и 32.

Проверки интерфейса: [UI_RESULTS.md](UI_RESULTS.md). Для № 02 остаётся сравнение с игроками, для № 45 — проверка на устройстве с настоящей экранной клавиатурой.

Проверки резервных копий, каталога игроков и метрик: [AUDIT_48_50.md](AUDIT_48_50.md). Запуск команд обслуживания и напоминаний: [DEPLOYMENT.md](DEPLOYMENT.md).
